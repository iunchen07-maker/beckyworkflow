# 待討論議題寫作規則（discussion-docs）

> **要防什麼**：`討論排程/` 長成第二座 SPEC——總覽變成幾萬字流水帳、結案議題賴著不走、新 session 把半年前的過程稿當現況讀。
> 機械檢查一句話：`$CLAUDE_WORKSPACE/scripts/check-discuss.sh <repo根>`（工具腳本未包含於此 repo；零 token、🟢🔴 輸出；History 只 ls 檔名、不讀內容）。

## 三桶分流（規則 1）

| 桶 | 放什麼 | AI 可讀？ |
|---|---|---|
| `討論排程/待討論/` | **只放還要討論的東西**（議題工作稿＋活清單＋總覽） | 讀 |
| `討論排程/素材/` | 參考資料（需求來源文件、外部系統研究、欄位目錄…）——**非議題、非禁區**，不會被「討論完」，SPEC 正文可引用 | 讀 |
| `討論排程/History_已討論完/` | 結案議題封存 | 🚫 禁區（名稱含 History） |

## 檔案只有三型（規則 2）

1. **工作稿**：一議題一檔，總有一天結案搬 History。
2. **活清單**：永不結案的持續維護檔（例：畫面清單、待問利害關係人清單）；總覽列出時**必標明「不是議題」**。
3. **總覽 `0_議題總覽.md`**：純索引。一支議題檔在總覽**只准一行**，不留內容複本。

## 總覽只列未決（規則 3・4・5）

- **✅ 出現次數目標＝0**：結案＝**把那一行刪掉**，不是標 ✅。歷史全部外包——
  拍板全史＝`Spec/memory/` 決策檔（一決策一檔，欄位見 `phase-0-spec-update.md` §SPEC 生命週期 3；切換前的舊史凍結在 `Spec/memory/legacy/`，含舊 `Spec/拍板紀錄.md`）｜定案全文＝SPEC 正本｜過程全文＝History 工作稿。
- **不放施工紀錄**：commit hash／branch 名／連動筆數／§節改寫清單一律不進總覽（那是 git 與決策檔的事）。
- **不留指向 History 的連結**（別給任何人一條走進禁區的路）。

## 警戒線＋棘輪（規則 6）

總覽 **≤6KB／60 行**；單一議題檔 **≤8KB**。超線＝已知債，**只能變小、不能變大**（同 file-discipline 棘輪；活清單不是議題檔，不吃 8KB 上限，但總覽上限照算）。

## 工作稿固定骨架（規則 7）

```markdown
> 狀態：🔵 討論中｜立案：YYYY-MM-DD｜用途：本議題新 session 的單一入口
## 立案緣由
## 要拍什麼
## 與既有線的界線
## 預期踩到
## 未決
## 方案選擇史        ← 討論過程只活在這一章，不散落他節
## 拍板紀錄
```

總覽每條議題附「**開講第一題**」——新 session 打開就知道從哪句問起。

## 結案 SOP＝原子 commit（規則 8）

四動作**同一個 commit**，缺一不可：

1. 殘留未決項先**內聯回總覽**（或專案的未結議題權威檔），不留指向禁區的指標
2. **決策檔就是紀錄**：本議題的 `Spec/memory/` 決策檔已寫好（欄位齊；「結論」段寫上工作稿檔名，日後才 grep 得回來），並跑專案腳本重產 `Spec/memory/index/` 各檔視圖（不手改）。**不再 append `Spec/拍板紀錄.md`**（已凍結進 `Spec/memory/legacy/`）
3. `git mv` 工作稿進 `討論排程/History_已討論完/`
4. 總覽**刪那一行**

遺漏由 `check-discuss.sh` 雙向勾稽把關（History 檔名 stem ↔ `Spec/memory/` 決策檔或 legacy grep 得到才算數）。

## 查結案紀錄的三步（不進禁區）

1. `grep -rl '<關鍵詞>' Spec/memory/` → 找到決策檔＝`date`＋結論＋`changes`（正本 §ID）；切換前的舊案在 `Spec/memory/legacy/`
2. `ls 討論排程/History_已討論完/ | grep '<關鍵詞>'` → 確認議題已封存（**只看檔名，不讀內容**）
3. `git log -S '<關鍵詞>' --oneline` → 全史回溯過程（走 git 層，不開禁區檔）
