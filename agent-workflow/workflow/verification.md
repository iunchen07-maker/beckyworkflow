# 驗證流程（verification）

> **要防什麼**：「寫程式的人自己出題、自己改考卷」。測試全綠，畫面卻是壞的；或者檢查失敗時，順手把檢查改鬆。
> 實際踩過的例子：新的 e2e 是寫程式的工人自己寫的；驗收紅燈後主流程自己放寬 grep；截圖只驗檔案大小、沒人看，結果畫面顯示原始 UTC 時間也沒被抓到。
> 依據：e2e 模擬真人動線、測試要獨立於作者、改動不得修改自己的檢查、新關卡先觀察再強制。

## 適用範圍

- **要走**：任何會改到程式碼的工作（前端、後端、腳本、migration、測試本身）。
- **不用走**：只改 SPEC、md 文件、mockup 文字的工作。判準＝diff 只碰 `*.md`／`Spec/` → 免。
- 一個工作同時改了程式和文件 → 要走。

## 六個步驟

### 1. 劇本測試先寫，而且由別人寫
- 由**另一個 agent** 寫，只給它：需求（工單目標／使用者要的行為）＋講好的畫面與 API 名稱（`data-testid`、路由、request／response 形狀）。**不給它看實作程式碼**。
- 用 Playwright 開真瀏覽器，模擬真人動線（誰、做什麼、看到什麼）。定位一律用 `data-testid`。
- 截圖用一般視窗大小，**禁止 `fullPage`**。
- **劇本在現在的程式上必須先失敗**；全綠代表它分辨不出改動有沒有做，退回重寫。
- 有難搞的邏輯（例：多人同時編輯同一份清單的衝突判定），另寫隨機測試：亂數產生幾百次操作，每次檢查「永遠要成立的規則」（例：沒按覆蓋，改動就不能不見；每筆待辦剛好屬於一個清單）。印出亂數種子，失敗才能重現。

### 2. 寫程式
- 寫程式的人**看得到**劇本，但**不能改**。驗收前會重新放一份正本進去，改過的直接被蓋掉。
- 覺得劇本寫錯 → 回報，不自己改（見步驟 5）。

### 3. 機器檢查（全部要過）
1. 工單／任務的驗收腳本。失敗時要印出**是哪一條**沒過。
2. 劇本測試＋隨機測試。
3. **畫面乾淨規則**（每一頁都跑）：畫面文字不得出現原始時間格式（帶 `T` 的 ISO 時間戳、未轉時區的 UTC）、`undefined`、`NaN`、`[object Object]`、沒翻譯的 i18n key。
4. **範圍檢查**：只改了允許改的檔案。
5. **舊測試沒被偷刪**：舊測試的標題比對改動前後；少掉的、或新加 `.only`／`.skip`／`fixme` 的，要在任務裡事先列出，否則不過。
- 不穩的測試不准靠重跑變綠。Playwright 維持不自動重跑；同一版程式同一條測試一紅一綠 → 記成「不穩」，另外修。

### 4. 看畫面
- 只看**有變動的畫面**，最多 5 張。
- 任務裡先寫一段「畫面上應該看到什麼」（3–6 條）；由另一個 agent 讀截圖逐條對照，寫下觀察。
- 給 PM 的總結附 2–3 張重點截圖。

### 5. 檢查本身寫錯時
- **誰都不能直接改檢查**（驗收腳本、劇本）。
- 走「留紀錄的跳過」：監工 agent 或主流程 Claude 可以跳過，**每個任務最多 2 條**，要寫原因，可附一條替代檢查；替代檢查存在任務的狀態裡，不改原本的檢查。
- 每次使用都列進給 PM 的決定清單（批次執行器：執行報告裡的決定清單；互動 session：當次總結）。之後整套驗收從頭重跑。
- 守門那幾條（工作樹乾淨、部署、smoke、全套 e2e）不能跳過。

### 6. 漏網的 bug 變成規則
- PM 或任何人抓到流程沒擋住的 bug：
  - 一整類的錯 → 加進「畫面乾淨規則」或共用檢查（一次擋住所有頁面）。
  - 只發生一次的 → 寫成劇本測試，放進回歸區。
- 同時回頭改本檔（見「怎麼改本檔」）。

## 誰在哪裡把關

| 步驟 | 批次執行器工單 | 互動 session |
|---|---|---|
| 1 劇本先寫 | 開工前叫劇本 agent；在現有程式上跑一次，必須先紅 | 收尾驗證流程：動手前派劇本 agent |
| 2 不能改劇本 | 劇本複製進工作樹設唯讀，驗收前重放正本 | 同左（驗收前重放） |
| 3 機器檢查 | 執行器驗收階段 | 收尾時跑，產出通過紀錄 |
| 4 看畫面 | 證據 agent 讀截圖，寫進證據檔 | 收尾時讀截圖，寫進給 PM 的總結 |
| 5 留紀錄的跳過 | 執行器的跳過紀錄 | 當次總結的跳過紀錄 |
| 6 漏網變規則 | 主流程 Claude（收尾檢查清單一條） | 同左 |
| commit／push | 執行器只在通過後部署、推送 | commit 前的守門 hook：改到程式卻沒有最新通過紀錄 → 擋（觀察期只記錄） |

## 怎麼改本檔

- 每次有漏（沒抓到的 bug、檢查誤擋），**在同一個 session 裡**改本檔。commit 訊息寫：漏了什麼、改了哪條規則。
- 本檔只寫現在的規則；改動歷史看 git log，不寫進檔案。
