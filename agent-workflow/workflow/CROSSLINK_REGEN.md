# 連結 regen — SPEC ↔ 索引 ↔ 圖 的交叉連結同步層

> 這份說明「為什麼需要 regen、它同步什麼、跨專案怎麼分層」。
> 實際步驟掛在 `phase-0-spec-update.md`（SPEC 收尾）與 `phase-1-product-design.md`（HTML 收尾）。
> 每個專案的**具體綁定**（工具路徑、圖是哪個檔）寫在該專案的 `CLAUDE.md`。

---

## 為什麼需要它

spec-driven 專案會把同一個 user story 串在多處：

- **SPEC 文字**（`Spec/<模組>/*.md` 的 `## US-X.Y` 段落）
- **索引**（`INDEX.md` 的 US 對照表：哪個 US 在哪個子檔、對應哪張畫面）
- **畫面**（`HTML設計稿/定案/*.html` mockup）
- **圖**（流程圖 / 功能樹，節點上掛「看 SPEC / 看畫面」連結）

這些之間的**深連結**會 drift：

- **段落深連結會壞**：在部分 Git 託管平台的 markdown 渲染下，`<a name>` 自訂錨**無效**；唯一能跳的是平台從**標題文字自動生成的 slug**（以專案實際使用的平台為準；常見演算法：`downcase → 移除 [^\w\-空格] → 空格換連字號`，**雙連字號不壓縮**）。標題一改字，slug 就變 → 既有連結失效。
- **畫面連結會壞**：mockup 增 / 刪 / 改名，索引的「畫面」欄與圖的 🖥️ 連結就對不上。

**regen = 一支冪等腳本，在訂版收尾把這些連結重算對齊**，並列出需人工補的東西。fragility 被「每次訂版重跑」吸收掉。

## 它同步什麼（兩個半邊，一支工具）

| 半邊 | 來源 | 同步什麼 |
|---|---|---|
| **SPEC 連結** | SPEC 標題文字 | INDEX「所在子檔」欄 → 段落深連結 `[子檔#slug]`；圖節點的 📄SPEC 連結 slug（以 `data-us` 為穩定鍵 → 標題改字也能重算） |
| **HTML 連結** | `定案/` mockup 檔 | INDEX「畫面」欄 → mockup URL（靠對應表）；圖節點 🖥️畫面 連結驗證 |

**只報告、不自動改的（人工 curate）**：mockup index 缺卡 / 份數對不上 / 圖的 🖥️ 連到不存在的檔 / 新 mockup 的 US 沒在對應表。→ regen 列出來提醒，補卡與加圖節點是人工。

## 什麼時候跑（3 個觸發時刻，都是「訂版」）

| 觸發 | 動作 |
|---|---|
| **SPEC 文字訂版**（改 / 加 / 刪 US、改標題） | Phase 0 收尾主動問 PM 跑 regen（同步 SPEC 連結半邊） |
| **HTML / 圖訂版**（mockup 拍板上架、流程改一步） | Phase 1 收尾主動問 PM 跑 regen（同步 HTML 連結半邊）+ 人工補卡 / 加圖節點 |
| —（同一支工具、冪等） | 兩個點都跑同一支；在任一點跑都會把全部對齊，不怕跑錯半邊 |

**原則：主動問 PM，不靜默自動跑**；問時列出它會做的事。

## 跨專案怎麼分層

```
$CLAUDE_WORKSPACE（共用）
├─ workflow/phase-0…, phase-1…   ← 通用步驟：「若專案有 regen 工具，收尾主動問 PM」
├─ workflow/CROSSLINK_REGEN.md   ← 本說明（概念）
└─ ~/.claude/agents/*.md         ← 通用 agents（動態讀上面規則書）

每個專案 repo（專屬）
├─ CLAUDE.md                     ← 綁定：宣告「我的 regen 工具路徑、我的圖是哪個檔」
└─ <專案工具目錄>/regen 腳本      ← 專案自己的 regen（寫死本專案路徑、MOCKUP 對應表、圖檔）
```

通用 workflow 說「該問 regen 了」→ 讀**當前專案 CLAUDE.md** 拿到綁定 → 跑該專案的 regen。

### 新專案要用它

1. 在專案 `CLAUDE.md` 宣告綁定：regen 工具路徑、「圖」是哪個檔（流程圖 / 功能樹 / …）。
2. 放一支該專案的 `regen_links.py`（照現有專案改路徑、`MOCKUP` 對應表、圖檔與連結樣式）。
3. 通用 workflow + agents 不用改，自動沿用本說明的收尾步驟。

> 目前 regen 腳本是各專案自有（寫死路徑）。等第二個專案實際採用，可把共用核心抽成 workspace 模板、專案只填參數。先不為假設過度抽象。
