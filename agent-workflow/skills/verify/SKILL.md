# verify — 直接寫程式的驗證流程

**規則正本＝`$CLAUDE_WORKSPACE/workflow/verification.md`（即本 repo 的 [`workflow/verification.md`](../../workflow/verification.md)）。每次載入都先讀它**（規則會一直改；本檔只寫互動 session 怎麼執行，不重抄規則）。

## 0｜判斷要不要走

`git diff --name-only`（含未 commit）只碰 `*.md`／`Spec/`／`討論排程/` → 免，直接收尾。其他都走。

## 1｜動手前：派劇本 agent

- 開一個 subagent，只給它：PM 要的行為（白話）、講好的 `data-testid`／路由／API 形狀、跑測試的指令與帳號。**不給它實作的檔案路徑或程式碼**。
- 它產出 Playwright 劇本（＋需要時的隨機測試）。劇本放在任務工作樹外（建議 `<repo>/../<repo>-stories/<任務>/`），跑之前才複製進去。
- 在**現在的程式**上跑一次：必須有紅。全綠 → 退回重寫。

## 2｜寫程式

- 不改劇本。覺得劇本錯 → 走第 5 步，不自己改。

## 3｜收尾：機器檢查

依規則正本「3. 機器檢查」逐條跑，**全部貼出指令與 exit code**：驗收腳本／劇本＋隨機測試（驗收前重新複製正本）／畫面乾淨規則／範圍檢查／舊測試標題比對。任何一條紅 → 還沒做完。

## 4｜看畫面

- 用 Read 打開有變動的截圖（最多 5 張，一般視窗大小），逐條對照「畫面上應該看到什麼」，寫下觀察。
- 給 PM 的總結附 2–3 張重點截圖路徑，並寫一句「我看到了什麼」。

## 5｜檢查寫錯時

不改檢查。在總結裡列「跳過紀錄」：哪一條、為什麼是誤判、替代檢查是什麼。每個任務最多 2 條；超過就停下來問 PM。

## 6｜通過紀錄

全過後寫一份通過紀錄（`<repo>/.verify/<HEAD 短 sha>.json`：各檢查的指令、exit code、截圖路徑、跳過紀錄），commit 前的守門 hook（未包含於此 repo）會檢查它。`.verify/` 不進版控。

## 收尾回報（給 PM）

做了什麼／每條檢查結果（貼實際輸出摘要）／看了哪幾張截圖、看到什麼／跳過紀錄（沒有就寫「無」）／還沒驗到的地方（沒有就寫「無」）。漏網的 bug → 依規則正本第 6 步改 `verification.md`。
